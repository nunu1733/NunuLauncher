## Findings

No blocking findings at any audit rev. The merge may proceed once the repository gate (`high-risk-gate` workflow) accepts this record on the docs-only head carrying it (see "Re-audit rev 5" verdict).

### 1. Spec wording pins "lock placement occupancy" in the projection; the implementation excludes the lock flag from the model leg

The accepted spec's Scope lists "lock placement occupancy" among the projection's required fields and its exclusion list does not name organizer lock state, while `ModelProjection.kt:29` explicitly excludes "organizer lock state" to the DB leg — and the spec's stop condition says a pinned field that is not faithfully recoverable from the model should reopen the design rather than shrink the projection. Resolution: the field is genuinely not model-representable (ADR-0004 stores it in a dedicated column the AOSP loader never reads into `BgDataModel` — grep-verified here), the DB leg retains it in full canonical equality and in the recovery manifest, and the direction of the exclusion is fail-safe (a weaker model leg can never produce a false success; it can only miss a loader corruption of a field the loader does not even carry). Under the reading "lock placement occupancy = the placements of locked items are verified", the projection satisfies the letter via its placement/structure fields. Recorded as a wording tension, not a violation; recommend recording the interpretation on Issue #152 and amending the spec's exclusion list in a follow-up docs commit so the next reader does not re-litigate it.

### 2. `BgDataModel` synchronization coverage in the capture is partial

`ModelProjectionCodec.capture` copies `workspaceItems`/`appWidgets`/`collections` under `synchronized(bgDataModel)` (L63–L69) but then reads `bgDataModel.collections` again for `membersByParent` (L73–L76) and `bgDataModel.lastLoadId` (L83) outside the lock. This is safe under the documented thread confinement — the capture runs on MODEL_EXECUTOR inside the #150 terminal-boundary completion, where `BgDataModel` mutation is model-thread-confined and the `synchronized` block is defense-in-depth — and any concurrent-shape surprise would throw into the `catch (Throwable)` fail-closed path (L55–L57), never a false success. Non-blocking; recommend either extending the lock to the remaining reads or stating the thread-confinement assumption in the codec KDoc.

### 3. Unit-level model-leg fixtures are single-app-icon; per-kind fidelity rests on the real-model lanes — addressed at `c667159347` (re-audit Fix 1/2)

The six new unit cases drive the model leg with a one-app-item fixture (`mutatingPlan()`), so the projection's folder/widget/app-pair/dock/legacy-shortcut branches are not individually asserted at the fake-seam level; `ModelProjectionCodec` itself has no JVM unit test (it requires Android `BgDataModel`/`UserCache`). Per-kind coverage exists instead through (a) the unchanged DB leg, whose fixtures cover folders/widgets/profiles/locks across the suite, and (b) the real-model instrumentation lanes, which pass the model leg end-to-end on-device (a misprojection of any kind present in the emulator workspace fails verification). This satisfies AC-152-05 at the seam level as the spec's oracle splits adapter/real-model vs fake-seam duties, but a dedicated DB-side `projectedToModelVerifiable` unit matrix (it is pure and JVM-testable) would close the letter more directly; recommend a follow-up test-maintenance Issue, not a merge blocker.

Resolution at the re-audit head: the recommended DB-side unit matrix now exists as `ModelProjectionTest` (unsupported-container representation, legacy projector threading, canonical ordering, planned-ref exclusion), and the legacy-shortcut branch is additionally asserted end-to-end at the fake seam by `sa12LegacyShortcutLaunchIntentDivergenceIsNeverApplied`. Remaining residue: `ModelProjectionCodec` still has no JVM test and folder/widget/app-pair per-kind projection fidelity at the fake-seam level still rests on the real-model lanes — the follow-up test-maintenance recommendation stands, downgraded to residual.

### 4. Excluded rows are symmetric and fail-safe — superseded for unsupported containers by re-audit Fix 2

Items the model cannot host (non-persistent refs, planned pages, `UnsupportedContainer`, containers below the desktop/hotseat sentinels — `ModelProjectionCodec.kt:113`, `ModelProjection.kt:91–110`) are dropped from both legs identically, and those rows remain covered by the full DB equality. A foreign extra workspace item in the model would appear in the snapshot but not the DB projection, failing equality — the exclusion set cannot mask a divergence on organizer-owned rows.

Superseded at `c667159347`: `UnsupportedContainer` rows (DB side and model side) are no longer dropped but represented explicitly with the raw container code (`ModelProjection.kt:133`, `ModelProjectionCodec.kt:116`), so a model that loses such a row fails verification instead of passing by symmetric omission. The remaining exclusions (planned references, non-persistent refs) are shapes the model never contains by construction, so symmetric exclusion is inherent, and the fail-safe property of the set is unchanged.

### 5. Gate-format limitation: `AC-152-NN` IDs cannot be machine-cited

Same condition recorded in the PR-175 audit: the hyphen-suffixed family is invisible to `_REQUIREMENT_ID_RE`, so the `Criteria:` line carries ADR-0004 and the spec criteria are verified in the body. The follow-up maintenance Issue recommended in pr-175 (extend the grammar to prefixed/suffixed `*-AC-NN` families or rename spec IDs) should absorb this instance.

### 6. Loader flag normalization can make the legacy launch identity diverge fail-closed for flag-less persisted rows (new, non-blocking, at `c667159347`)

The two canonical forms correspond exactly (`LoaderCursor.java:185` parses the persisted text with `Intent.parseUri(text, 0)`; both legs then serialize with `toUri(0)`), except that the loader mutates legacy-shortcut intents at load time: `WorkspaceItemProcessor.kt:303–314` adds `FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` for rows whose action is `ACTION_MAIN` with `CATEGORY_LAUNCHER` — precisely the historical auto-added-shortcut class the AOSP comment targets, which by definition may lack those flags in the persisted text. `toUri(0)` emits `FLG=`, so for such a row the model-side identity carries the added flags while the DB-side re-serialization does not, and the model leg reports divergence. The direction is fail-closed (a legitimate apply fails `VERIFICATION_FAILED` and routes to automatic recovery; no false success is possible — the DB leg still pins the raw text), and the emulator lanes passed because no such row was present. Recommend a follow-up: mirror the same flag heuristic in `LauncherLayoutAdapter.legacyLaunchIdentityOf` (or mask `FLG` in the canonical form) and add a real-model row with a flag-less legacy shortcut to the instrumentation matrix. Not a merge blocker.

Resolved at `a482141c33` (rev 4) and narrowed at `f02ad02751` (rev 5): the canonical form masks exactly the two loader-managed bits via `canonicalLegacyLaunchUri` (`ModelProjectionCodec.kt:55`, applied at `LauncherLayoutAdapter.kt:434` and `ModelProjectionCodec.kt:162`), pinned by `ModelProjectionTest.legacyIdentityMasksOnlyTheLoaderManagedBits` and proven on-device with the three-verdict matrix by `RealAdapterRowMatrixInstrumentationTest.legacyShortcutLaunchIdentityMasksOnlyLoaderFlags`; at rev 5 the mask applies only under `isLoaderManagedShortcutLaunch`, mirroring the loader's own `ACTION_MAIN` + `CATEGORY_LAUNCHER` normalization condition. The rev-3 whole-`FLG` mask (`f554a5dae1`) removed the fail-closed divergence but over-masked — hiding non-loader launch-flag semantics — and rev 4's unconditional two-bit mask still over-masked non-normalized intent shapes; both were superseded after the maintainer re-reviews. The instrumentation-matrix follow-up is likewise closed by the new on-device test. No follow-up remains.
