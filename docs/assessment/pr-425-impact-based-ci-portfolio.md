## Findings

- Nothing blocking merge. All machine-checkable claims reproduced independently at the audited head; all six demo patterns match the spec scenarios, including the layout_write over-trigger on the db-schema demo (documented, safe-direction overlap) and the docs-only run skipping even permanent gates (validate-repo-contract still runs, as contracted).
- Post-merge follow-up (per spec AC-422-05 / plan): first weekly scheduled run and the first main-push full run must be recorded in Issue #422 as follow-up evidence; the main-push full sweep run 35950633020 completed success and is recorded in this document.
- Known flaky surfaces #352 (`ExchangeFlowStateHolderTest`) and #418 (Compose timeout signature) each required a classified rerun on this PR; both were classified per the new policy (comments 5805741873, 5806540525) and the final head run is green — this is the policy working as designed, not a residual defect, but the underlying tracking issues remain open.
- Observation (non-blocking): on `*-dev` branch push events, dorny/paths-filter evaluates the diff against the default branch, so the change set is the cumulative increment (a conservative superset) rather than the branch-local delta; per-increment judgment belongs to `pull_request` events. This is measured and documented in `ci-test-portfolio.md`; the demos therefore used draft PRs against `issue-422-implementation`.
- Observation (non-blocking): `final-status` aggregation treats skipped required jobs as success by design; this semantics is documented in the portfolio doc and its needs list is machine-locked to the map file, so silent coverage loss would require a coordinated map+workflow+validator drift, which the bidirectional vocabulary check makes unlikely.
