## Findings

Pass-with-findings — no blocking findings. The merge may proceed once the repository gate accepts this record; the findings below are follow-up items, none of which weaken the layout-data safety properties.

### 1. (minor, evidence gap) No automated ja-locale assertion for the 15 new string keys (AC-12)

`ManualOrganizationPreferencesInstrumentationTest.japaneseResourcesResolveEveryConcretePreviewString` — the established oracle asserting that concrete-preview strings resolve under a `Locale.JAPAN` configuration context rather than falling back to English — was not extended with the new #228 keys (`manual_organization_missing_apps_*`, `manual_organization_group_added`, `manual_organization_preview_add_descriptor`, `manual_organization_preview_add_row`, `manual_organization_preview_unavailable_add`, `manual_organization_preview_retry`, `manual_organization_added_count`, `manual_organization_applied_added_count`, `manual_organization_detecting_missing_apps`, and the checked/unchecked `stateDescription` pair). The keys are present in `values-ja/strings.xml` (verified in the diff) and English resolution is asserted on-device, but the spec's test oracle for AC-12 ("ja configuration contextでのstring解決test") is not discharged in-repo for the new keys. Recorded in the PR as an owner-confirmation item; recommend extending the ja test in a small follow-up PR so the coverage is mechanical rather than manual. Not a merge blocker: a missing ja value would render the English string, not corrupt layout data.

### 2. (minor, contract-documentation gap) Spec 13's closed `PreWriteRejection` set was not amended for `CANDIDATE_UNAVAILABLE`

`specs/13-safe-layout-application/spec.md` defines `PreWriteRejection` as a closed set (L255–261) and `ApplyResultContractTest` asserts the runtime enum "must match spec exactly" — this PR adds `CANDIDATE_UNAVAILABLE` to both the enum and the test's expected set, but spec 13's definition and change history are untouched. The Issue #185 precedent (spec 13 change history, L645: "Issue #185 extended the closed `PreWriteRejection` set") amended the spec when the set grew. The extension itself is required by accepted spec 228 §6 and is additive/fail-closed, so this is a 正本-consistency follow-up, not a safety issue: amend spec 13's set and change history (or record the #228 extension there) in a docs-only follow-up, per AGENTS.md's rule that contradictions are fixed in the owning document first.

- The nullable-port design is fail-closed in both directions: a null `CandidateAvailabilityPort` with a candidate-carrying plan rejects (`candidatePlanWithoutAPortFailsClosed`), and a null `CandidateApplicationResolver` makes candidate materialization `Result.Invalid` — legacy test wiring cannot silently admit candidates.

- Determinism/property coverage is strong for a planning change: shuffled-input ordering, selection-order insensitivity, per-strategy composed invariants (`everyStrategyKeepsTheComposedInvariantsAndEmptySelectionEquality`), and idempotence-after-placement (`planningOscillatesNothingAfterTheCandidatesArePlaced`).
