### 1. (round-1 record) BLOCKED verdict on the prior head and its resolution

Round 1 (head `70a3b09cd6`, run 34674075420) was blocked by a deterministic failure in the PR's own AC-9 picker oracle: the catalog grew from six to eight rows inside the picker's single non-virtualized LazyColumn item, whose code comment recorded a now-false "Six rows fit one screen" assumption; on the CI emulator (Pixel 7 Pro, API 36) the tail rows composed below the fold and `assertIsDisplayed` failed at exactly the first row this PR added — twice, across a full rerun of the failed jobs. Per the audit contract no passing record was written. Commit `637be019b5` resolves it correctly and minimally: the test now scrolls each row into view before asserting (`onNode(hasScrollAction()).performScrollToNode(hasText(...))`, the established pattern), and the stale comment is corrected — the picker item deliberately stays non-virtualized so the whole radio group keeps its `selectableGroup` a11y contract, with rows merely composed off-screen on small viewports. The delta commit changes **no production behavior** (comment-only in product code), so all round-1 per-criterion verdicts carry forward; the previously failing test and both new strategy rows are green in run 34675542506.

### 4. (assessment) Test-harness `Oracle.kt` extension does not weaken prior guarantees

The idempotence oracle still fails any replanned item that is `Moved` or whose target changed — those checks run before and independently of the reason check, for widget-stream items too. The extension only relaxes the *preserve-reason* expectation, and only when the V1 expectation is `WIDGET` under a strategy that declares a `widgetPolicy`, accepting exactly the three truthful stable reasons the spec defines (`ALREADY_CANONICAL`, `STRATEGY_PRESERVED`, `NON_TARGET`); every other item — including locked/unavailable/dock widgets, whose expectations precede the widget branch — keeps exact-reason equality, and non-widget-capable strategies keep the original strict path entirely.

### 5. Minor observations (non-blocking)

- `placeWidgetStream` accumulates trial rectangles into the per-page obstacle list it borrowed from the `pageObstacles` map rather than a defensive copy; each list is consumed exactly once (pages are independent), so behavior is correct, but a copy would be more obviously single-use.
- The `BOTTOM_UP_ROW_MAJOR` arm of the `rowWindow` extension in `findRowMajorFirstFit` is currently unreachable from the widget stream (which always scans `TOP_LEFT_ROW_MAJOR`); it is implemented symmetrically for future policies and exercised by no test of its own — the follow-up child issues (`GLOBAL_COMPACT_V3`, `CATEGORY_CONTIGUOUS_V2`) should bring their own fixtures over it.
