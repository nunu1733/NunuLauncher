# build-cache-echo実証トランスクリプト（2026-10-06 調査session）

Issue #537根因チェーン5/6（破損compile出力のbuild cache保存・復元と`--rerun-tasks`による回復）のコマンドとキャプチャ出力。出力行は調査sessionで実際に取得したものの転写である。

> 証拠強度の注記（2026-10-07追補）: §1〜§4はbuild全体の集計行までの保存で、task単位の`FROM-CACHE`行は未保存。task単位の直接観測は§5（修復後のcache状態での追補実験、2026-10-07実施）で取得した。§1の「破損出力そのものがcache経由で復元された」は直接観測ではなく、§5の観測と整合する最有力の推論である（assessment本文の根因チェーン5/6参照）。

## 5. task単位のcache-hit直接観測（追補実験、2026-10-07、修復後のcache状態）

`--rerun-tasks`でcache entryが正常出力に置き換わった後の状態で、3つ目のfresh worktree（`/Users/nunu/Documents/work/NunuLauncher-537-clean3`、`575e37baad`、build dir空）の`:compileLawnWithQuickstepGithubDebugKotlin`を単独実行し、task単位の出力をconsole=plainで記録した。同じ入力（`575e37baad`のsource）に対してcompile taskのoutputがbuild cacheから提供されること、およびその出力が`$stable`を含む健全なものであることを直接観測できる。

この観測が示すこと: (a) この追補実験の条件下（同じ入力hashのfresh build dir）で、対象compile taskの出力がbuild cacheから復元された（§1の集計行`377 from cache`と整合）。(b) 現在のcache entryは健全な出力である。(c) したがって§1の時点でcache復元により破損出力が流れたという説明は、観測済みの事実すべてと整合する最有力の推論である。ただし§1のtask単位ログは未保存のため、「初回fresh worktreeでcompile task自身がFROM-CACHEだった」ことの直接観測は存在しない。
