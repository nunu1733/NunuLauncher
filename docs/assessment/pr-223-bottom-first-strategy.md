## Criteria check

- **Spec §BOTTOM_FIRST_V1 normative rule 1 — "Folder/unit/page policy identical to CANONICAL_PAGE_COMPACT_V1; only the cell traversal changes" — PASS.** Field-by-field descriptor comparison in `LayoutStrategyRegistry.definitions`: `createsFolders` true/true; `eligibleUnitFilter` lambdas textually identical (`it.kind == ItemKind.APPLICATION || it.kind == ItemKind.DEEP_SHORTCUT`); `unitOrder` `CANONICAL_TIE_BREAK`/`CANONICAL_TIE_BREAK`; `pageScope` `PREFERRED_THEN_NEW`/`PREFERRED_THEN_NEW`; `placeFullRun` `FullRunExecution::execute`/same. The only differing field is `cellTraversal` (`TOP_LEFT_ROW_MAJOR` vs `BOTTOM_UP_ROW_MAJOR`). Both definitions dispatch to the same `executeCanonicalPageCompact` body (`FullRunExecution.execute` branches on `unitOrder`), so grouping, folder formation, unit ordering, page grouping and preservation are literally shared code, not reimplementations.
- **Spec §BOTTOM_FIRST_V1 normative rule 2 — traversal semantics "candidate top-left y from rows - span.height down to 0, x left-to-right" — PASS (independently verified twice).**
  - *Static proof*: `findRowMajorFirstFit` (`PlacementAllocator.kt:105–153`) builds BOTTOM_UP candidates as `{rows-h} ∪ {rect.y - h | rect ∈ occupied}`, filtered `≥ 0`, distinct, descending. Mirror of the TOP_LEFT set `{0} ∪ {rect.bottom}`: if the maximal valid `y*` were not a candidate, then `y* < rows-h` and no occupied rect starts at `y*+h`; the only row newly covered by moving up to `y*+1` is `y*+h`, and any blocker there would either intersect the valid region `[y*, y*+h)` (contradiction) or start exactly at `y*+h`, making `y* = top - h` a candidate — so `y*+1` is valid, contradicting maximality. Hence the maximal valid `y` is always in the candidate set, and the descending scan returns (max valid y, min valid x at that y) — exactly first-fit in the spec's scan order. The x-direction blocking-interval sweep (`PlacementAllocator.kt:136–150`) is shared verbatim with the TOP_LEFT branch, so "x left-to-right" has identical semantics in both traversals. The `y + h > rows` break is unreachable for BOTTOM_UP (every candidate ≤ `rows-h`) and harmless.
  - *Empirical proof*: a brute-force reference implementing the spec sentence literally (y descending `rows-h..0`, x ascending, overlap-checked first fit) was fuzz-compared against a faithful port of the implementation over 200,000 randomized cases (grids 1×1..7×7, spans up to full grid, non-overlapping random occupied rect sets, seed `0x4E554E55`): **0 mismatches**, including multi-span units, fragmented occupancy, and no-fit cases.
  - *Occupancy constraints*: `PlanningPlacement.place` marks `reservedWorkspaceRegions` and every `determinePreservation != null` item (locked, unavailable, dock, widget, app pair, legacy shortcut, non-target, folder-member) via `Allocator.markOccupied` before any strategy runs, and `markOccupied` is traversal-independent (pure rect insertion). Locked skip is asserted by `lockedCellsAreSkippedByTheBottomUpScan` (L-17 variant: locked app at `(3,4)` preserved with `PreserveReason.LOCKED`, ten apps fill `(0,4)..(2,4)`, `(0,3)..(3,3)`, `(0,2)..(2,2)` — independently recomputed against the algorithm). Multi-span blocking is asserted by `multiSpanUnitsOccupyTheirBottomCellsAndBlockTheScan` (2×2 existing folder moves as one unit to `(0,3)` on 6×5 and its full region blocks rows 3–4 columns 0–1; independently recomputed: apps land `(2,4)..(5,4)` then `(2,3)..(5,3)`).
  - *Incremental runs* keep `TOP_LEFT_ROW_MAJOR` regardless of selection (`PlanningPlacement.kt:26–27`), consistent with spec 182's "strategies govern full organization only"; pre-existing child-2/3 behavior, unchanged here.
