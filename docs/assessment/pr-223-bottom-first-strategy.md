## Criteria check

- **Spec §BOTTOM_FIRST_V1 normative rule 1 — "Folder/unit/page policy identical to CANONICAL_PAGE_COMPACT_V1; only the cell traversal changes" — PASS** (verified in full at round 1; production code byte-identical since): field-by-field descriptor comparison in `LayoutStrategyRegistry.definitions` shows `createsFolders`, `eligibleUnitFilter` (textually identical lambda), `unitOrder`, `pageScope` and `placeFullRun` all equal to the canonical definition; only `cellTraversal` differs (`TOP_LEFT_ROW_MAJOR` vs `BOTTOM_UP_ROW_MAJOR`). Both definitions dispatch to the same `executeCanonicalPageCompact` body, so grouping, folder formation, unit ordering, page grouping and preservation are shared code, not reimplementations.
- **Spec §BOTTOM_FIRST_V1 normative rule 2 — traversal semantics "candidate top-left y from rows - span.height down to 0, x left-to-right" — PASS (independently verified twice at round 1, still valid):**
  - *Static proof*: `findRowMajorFirstFit` (`PlacementAllocator.kt:105–153`) builds BOTTOM_UP candidates as `{rows-h} ∪ {rect.y - h | rect ∈ occupied}`, filtered `≥ 0`, distinct, descending — the exact mirror of the TOP_LEFT set `{0} ∪ {rect.bottom}`. If the maximal valid `y*` were not a candidate, `y* < rows-h` and no occupied rect starts at `y*+h`; the only row newly covered by moving up to `y*+1` is `y*+h`, and any blocker there would either intersect the valid region `[y*, y*+h)` (contradiction) or start exactly at `y*+h`, making `y* = top - h` a candidate — so `y*+1` is valid, contradicting maximality. The descending scan therefore returns (max valid y, min valid x at that y) = first-fit in the spec's scan order. The x-direction blocking-interval sweep is shared verbatim with the TOP_LEFT branch, so "x left-to-right" has identical semantics in both traversals; the `y + h > rows` break is unreachable for BOTTOM_UP and harmless.
  - *Empirical proof*: brute-force reference implementing the spec sentence literally (y descending `rows-h..0`, x ascending, overlap-checked first fit) fuzz-compared against a faithful port of the implementation over 200,000 randomized cases (grids 1×1..7×7, spans up to full grid, non-overlapping random occupied rect sets, seed `0x4E554E55`): **0 mismatches**, including multi-span units, fragmented occupancy, and no-fit cases. Re-run at this round confirmed 0 mismatches again; `PlacementAllocator.kt` is unchanged between the two heads, so the result applies verbatim to the audited head.
  - *Occupancy constraints*: `PlanningPlacement.place` marks `reservedWorkspaceRegions` and every `determinePreservation != null` item (locked, unavailable, dock, widget, app pair, legacy shortcut, non-target, folder-member) via `Allocator.markOccupied` before any strategy runs, and `markOccupied` is traversal-independent. Locked skip is asserted by `lockedCellsAreSkippedByTheBottomUpScan` (L-17 variant, expectations independently recomputed); multi-span blocking by `multiSpanUnitsOccupyTheirBottomCellsAndBlockTheScan` (2×2 existing folder at `(0,3)` on 6×5 blocking rows 3–4 columns 0–1; independently recomputed).
  - *Incremental runs* keep `TOP_LEFT_ROW_MAJOR` regardless of selection (`PlanningPlacement.kt:26–27`), consistent with spec 182's "strategies govern full organization only"; pre-existing behavior, unchanged.
