## Findings

1. **CI attempt-1 failure — flaky, independently attributed, cleared by re-run on the identical SHA.** Attempt 1 of run 33936797437 failed `organizer-instrumentation-issue52-tests` and therefore `final-status`: `ManualOrganizationPreferencesInstrumentationTest.changeListTraversalReachesExpandAndReviewActions` — `AssertionError: Failed to assert the following: (Focused = 'true')` at `pressDownUntilFocused` (test source line 612/647): after 12 DPAD_DOWN presses the `[Show all 6 items]` node existed and rendered (`Focused = 'false'`, `StateDescription = 'Collapsed'`) but window focus had not reached it. Attribution to flake, not to this diff: the test injects a fake `OrganizationPlanner` and a fully synthetic six-move `PlanPreviewDetails` (production planning code never executes), the PR changes no UI/test/resource file, the identical test passed on the base commit `05f37443a4` (push run 33899989511) and on the child-2 head (run 33884482040), and the PR #202 audit record documents the exact same test and assertion signature as an emulator window-focus flake cleared by re-running the failed jobs on the identical SHA. The lane log additionally shows startup adb-daemon retries and an emulator `Failed to find ColorBuffer` GPU error. The auditor re-ran the failed jobs (`gh run rerun 33936797437 --failed`); attempt 2 completed with the lane 27/27 green and `final-status` success — the flake attribution is confirmed by non-reproduction on the identical SHA.
2. **Unused executor branches for later children — recorded, not a defect.** `CellTraversal.BOTTOM_UP_ROW_MAJOR` (child 5 `BOTTOM_FIRST_V1`), `PageScope.CAPTURED_THEN_NEW` in the full-run executor (child 6 `GLOBAL_COMPACT_V1`), and `UnitOrdering.CAPTURED_VISUAL_PAGE_LOCAL`/`CAPTURED_VISUAL_GLOBAL` (children 4/6/7) are unreachable from the registered strategy set: the only definition declares TOP_LEFT/PREFERRED_THEN_NEW/CANONICAL_TIE_BREAK, and unimplemented orderings throw `IllegalStateException` at dispatch instead of silently running another strategy's layout. This is the loud-failure design the PR describes; it must be revisited when those children register their strategies.
3. **Incremental run is strategy-independent by design — consistent with spec.** `place` forces `TOP_LEFT_ROW_MAJOR` for `IncrementalPlacement` and keeps the pre-182 canonical flow byte-identical (verified above). The spec 182 catalog columns govern full-organization runs; the incremental path is not a catalog member's behavior. Recorded so a later child does not "fix" this into a strategy leak without a spec change.
4. **`eligibleUnitFilter` currently scopes only app units; existing folders stay unconditional units** (matching the old `placeFullRun` exactly). When children 4/7 need folders as fixed constraints (`STRATEGY_PRESERVED`), the declared descriptor will need an additional field or executor branch; today's shape is sufficient for CANONICAL only. Informational for child-issue planning, no action needed here.
5. **Style surface note (informational).** `tests/organizer-instrumentation/**` remains outside the spotless target list (unchanged from the PR #207 record); this PR touches no such file.
