## Bug oracle and change

At the base revision, `LauncherLayoutAdapter.dbDesktopPageIds(false)` reads desktop screens `[0,1]`, does not synthesize page 0, then filters page 0 from the actual row-derived list and returns `[1]`. The accepted #155 page rule requires the capture to preserve row-backed screens; suppressing synthesis while QSB is OFF does not authorize removing a page that has a desktop row.

The adapter now prepends Launcher `FIRST_SCREEN_ID` only when QSB is enabled or the desktop row set is empty, then appends every row-backed page. SQL numeric ordering remains intact and `distinct()` retains page 0 once. No writer, schema, recovery format, public interface, or dependency changed.

The #155 spec and plan now say explicitly that QSB OFF suppresses only synthesis of a rowless first page. Both retain the accepted enabled/empty fallback rule.
