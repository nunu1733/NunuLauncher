## Findings

Pass — the production defect is real, correctly fixed, and its AC-10 evidence is complete; no blocking findings.

### 1. The AC-10 production defect and its fix, independently re-derived

The #296 audit's pending AC-10 evaluation surfaced a genuine production defect that all prior JVM fixtures had missed: the production composer `FullTargetSetMaterializer` marks **every** `APPWIDGET`/`CUSTOM_APPWIDGET` item `ExistingRole.Preserved` by kind (widgets are never user-selected organization targets — a pre-#235 rule, read directly by the auditor at `FullTargetSetMaterializer.kt`), so under #296's parameterized-but-non-terminal widget branch every production widget fell through to `NON_TARGET` and the widget stream never fired; the planner fixtures had used `Movable`-role widgets and could not catch it. The broken-preview evidence image documents this exactly (widget-capable strategy selected, app-only moves, no widget rows). The fix makes the widget branch terminal for widget kinds, which matches the production reality: the user-facing scoping of widget relocation is the strategy selection (the `widgetPolicy` declaration) itself, not the target-set role. The auditor verified the fix's blast radius is exactly the production case: the only items whose disposition changes are widgets under widget-capable strategies whose role is `Preserved` (previously `NON_TARGET`); app-pair-member/folder-member/unsupported-container widget placements cannot reach planning at all (validation rejects them via the membership kind rules and V-02), so the branches the terminal widget branch now skips have no reachable widget inputs; locked/unavailable/reserved/Dock widgets keep their higher-precedence fixes; non-widget-capable strategies and the incremental tail are byte-identical. The spec amendment (eligibility rule + change-history row) keeps the accepted normative text and the implementation saying the same thing, and the AC-10 evidence assets document the full before/preview/after chain on device.
