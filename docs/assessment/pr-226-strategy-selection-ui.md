## Criteria check

- **Spec 182 §Selection contract write authority items 1–4 / AC-3 — PASS.** The picker never writes storage and never passes a selection value to the composer: the only write call site is `LayoutStrategySelectionModule.store(context).select(id)`, and the UI state after success is taken from the **returned published snapshot** (`write.snapshot.selection`), not the request. Write-time catalog validation, atomic generation/digest publication, and failure-preserves-selection live in `LayoutStrategySelectionStore.kt` (child 2, unchanged) and are pinned by `LayoutStrategySelectionStoreTest` (`unsupportedStrategyIsRejectedAtWriteTimeWithoutTouchingStorage`, `writeFailureKeepsTheExistingSelectionIntact`, `validatedWritePublishesAtomicallyWithNewGenerationAndDigest`). All non-`Committed` results are ignored by the UI: the previous selection stays displayed and no run restarts — the spec's "does not start a new run" holds. UI-level failure feedback remains a tracked follow-up (Findings 3).
- **Spec 182 §Preview integration "fresh compose/plan cycle" / spec 52 §Coordinator (no snapshot reuse) — PASS.** On a committed change while a run is active the code issues `dismiss()` then `start(trigger)`. `dismiss()` cancels only pre-admission operations (writes nothing; `applicationAdmitted` → `ApplicationInProgress` no-op), and `start()` always runs `application.composeFullOrganization()` — a fresh capture whose composer read observes the newly published snapshot; there is no in-run substitution path (the composer reads the store itself, `OrganizationInputComposer.kt:190–212`). During `Applying` post-admission, `dismiss()` returns `ApplicationInProgress` without state change and `start()` returns `Busy`, so an in-flight application is never restarted. Store writes are serialized under the store lock; rapid taps converge through the same guards.
- **Spec 182 §Failure layering / AC-3 fail-closed double defense — PASS.** Store read failure → `readSelectedStrategy` returns null → the picker renders with **no** active selection (never a silent default), while the composer independently returns typed `NotReady` (`SourceUnreadable` / `UnsupportedVersion`). Catalog read failure → `strategyCatalog == null` → picker hidden. A persisted selection outside `runtimeSupported` remains composer `NotReady(UnsupportedVersion)` (child 2, re-verified in source).
- **Spec 182 §Preview integration consequence counts / spec 194 PP-AC-07, PP-AC-12 one-truth — PASS.** Both counts are computed inside `PlanPreviewProjector.project` from the same `changes` list published as the change rows, so header and rows cannot diverge; the `Summary`/`PreviewCounts` split is untouched (the "Strategy:" line is input context rendered from `Summary` in both modes, consistent with the documented §D2 rule that the truth split covers change counts only). `pageDisplayOrdinal` spans persistent + planned pages, so moves onto new pages count as cross-page. `PlanPreviewProjectorTest.strategyConsequenceCountsSplitCrossPageMovesAndStrategyPreservedRows` pins the separation. ## Findings

1. **Resolved (round-1 Blocking 1) — picker placement.** Moved to the end of the `PreferenceLazyColumn`; all pre-existing rows keep their original order and positions, the 12 broken MFO-15/195 tests are green in CI on the audited head, and the picker is reachable in every run state. The screen's primary review actions are no longer pushed below the fold.
2. **Resolved (round-1 Blocking 2) — TalkBack label announcement.** `contentDescription` removed; the merged radio node announces name + description + selected state. Remaining nit: the `androidx.compose.ui.semantics.contentDescription` import is now unused in the file (style tooling does not police it; remove in the next code-touching PR here).
3. **Medium (tracked, non-blocking) — write failures stay silent at the UI.** `else -> Unit` satisfies the spec's normative requirements (previous selection intact, no new run, store untouched), and the preservation is passively observable (the old selection remains displayed), but a `WriteFailed`/`BundleUnavailable` result produces no explicit announcement. Spec 182 names no failure-feedback requirement, so this does not gate the merge; recommend a live-region announcement in a follow-up (child 9 evidence or UI cleanup).
4. **Low — `crossPageMovedCount` counts Workspace→Workspace moves only.** A `Moved(FOLDER_MEMBER)` placement whose new folder lands on another page is not counted because `PlacementTarget.FolderMember` carries no page (the folder's own placement is the separate `NewFolderChange` row). Faithful to the placement vocabulary (spec 194 forbids reinterpreting it); recommend pinning the definition in a spec/CONTEXT note so the GLOBAL_COMPACT scenario sentence stays unambiguous.
5. **Low — main-thread store read.** `readSelectedStrategy(context)` runs a file read inside `remember {}` during composition, deviating from the `CategoryOverridePreferences` `Dispatchers.IO` pattern; small file, worth aligning in a follow-up. Related: selection is read once per composition, so an external change while the screen is open is not re-read (the composer always re-reads; acceptable).
6. **Low — `dismiss()`-during-`Recovering` entry point.** The picker stays clickable during `Recovering`; a committed selection then calls `dismiss()`, which releases the recovery lease while `application.confirmRecovery` executes on another IO thread (pre-existing `dismiss()` semantics shared with the back button; DB safety preserved by the application-layer transaction and revision/precondition gates). Consider gating picker restarts to pre-`Applying` states.
7. **Nit — copy.** `organization_strategy_unknown_name` "Custom strategy"/「カスタムストラテジー」 labels a future *built-in* member without a string mapping; a neutral wording would fit better. The added `manual_organization_strategy_section` line in `values-ja/strings.xml` starts at column 0 (indentation inconsistent; res XML is not spotless-policed).
